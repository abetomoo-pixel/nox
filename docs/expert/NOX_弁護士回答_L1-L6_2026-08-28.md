## L1 の補足（誤解しやすい点の明確化）

2025年改正風営法で「キャスト負担の売掛は禁止された」「キャストへの売掛負担は○％まで」という規定が新設されたわけではない。改正法が直接狙っているのは客側の売掛を作る過程と悪質な取立て（料金の虚偽説明・恋愛感情につけ込んだ飲食要求・料金支払い等を目的とする威迫・売春等による金銭取得の要求などの禁止）。

なので NOX の「客A 売掛 100,000円 → 担当キャストAの負担債権 100,000円 → 給与・報酬から20,000円ずつ回収（oldest-first）」が2025改正風営法だけを理由に直ちに禁止、という結論にはならない。ただし実際には別の法律が刺さる: 雇用なら S1/S2（賃金から店の債権を勝手に回収する話）、委託なら L3（フリーランス法上の報酬減額・経済的利益提供要請等）。

したがって NOX では、売掛管理→キャスト負担→給与・報酬から回収を**一続きの処理にしない**:

```
customer_receivable
    ↓
cast_liability        ← 負担根拠を記録
    ↓
settlement_request
    ↓
payroll deduction     ← 雇用/委託別チェック
```

そして「売掛不可」設定は持った方がいい:

```
receivable_policy
 ├─ disabled
 ├─ customer_only
 └─ cast_liability_allowed
```

全店舗がキャスト負担売掛を採用するわけではない。法的理由以前に、機能として切れる器が必要。

## L2 の補足（retention 設計）

「audit_logs 全件・削除なし」ではなく retention_policy を持たせる:

| データ | 基本方針 |
|---|---|
| 賃金計算・勤怠・労務根拠 | 最低3年、将来5年への移行を想定 |
| 売掛帳・会計記録 | 原則7年 |
| 税務書類 | 書類ごとの法定期間 |
| マイナンバー | 必要期間のみ、その後速やかに削除 |
| CRM | 利用目的上必要な期間 |
| 操作監査ログ | セキュリティ上必要な期間 |
| PIIアクセスログ | セキュリティポリシーで設定 |

DB 設計としては `legal_min_retention_until` / `scheduled_delete_at` / `anonymize_at` / `deletion_hold` あたりを持つと後から困らない。「監査ログだから永久保存」は避ける — ログ自体に氏名・顧客ID・給与変更履歴等が大量に入れば、それも個人データになり得る。

## L3 の補足（委託の扱い）

雇用なら penalty_limit＝労基法91条をシステムで強制できる。一方、委託については「罰金は報酬の10%まで」のような全国共通の法定数値がない。だから NOX 独自に「20%までなら合法」といった上限を作るのは逆に危険。

代わりに、委託でノルマ未達減額・定額罰金・当欠罰金・売掛負担を設定するとき「契約条件への明示確認」を必須にし、「既に確定した報酬から控除する設定は、フリーランス法上の報酬減額等に該当する場合があります」という警告を出す。公取委は、手数料などを差し引いて支払う場合でも、フリーランス側に責任がなければ報酬減額になり得ると説明している。

C2 ともつながり、減額・罰金型より「基本報酬＋成果報酬」型の方が NOX として扱いやすい。

## L4/L5 の補足（削除と法定保存の分離）

退職時に cast.status = retired になったから即 DELETE cast はダメ:

```
退職 → 業務利用停止 → 不要PII削除（写真・LINE ID・プロフィール）
     → 法定保存データ保持（氏名・給与・勤怠・税務）
     → 保存期間終了 → 削除/匿名化
```

マイナンバーは一般プロフィールから完全分離。casts に my_number を普通のカラムとして置く設計は避ける:

```
cast_tax_identifiers
 encrypted_value
 key_version
 authorized_role
 collected_at
 legal_purpose
 delete_after
```

## L6 の補足（規約の構造）

BANZEN 案と同型の「NOXは店舗が設定した計算規則を実行するものであり、労働関係法令、税法その他法令への適合性については店舗が確認するものとする。」は入れてよい。ただしこれ一本ではなく:

- ① NOX 自身が法定値を守る領域: 深夜時間帯・最低賃金チェック・雇用の減給制裁上限・税計算・保存期間
- ② 店舗判断の領域: 雇用か委託か・契約上の報酬体系・売掛負担契約・ノルマ・社会保険加入判定に必要な事業所情報

そのうえで「NOX＝計算エンジンとしてルールを実行／店舗＝契約関係・事実関係・入力値・法的区分を決定」という責任分担にする。
