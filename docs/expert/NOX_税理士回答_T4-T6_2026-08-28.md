| T4 料金項目の税区分（C3） | 項目ごとに税区分を持つ設計でよい。むしろ持たせるべき。課税10% / 課税8% / 非課税 / 不課税 などを料金マスター側に持てる構造が安全。ただし夜職店舗の通常料金であるセット料金、指名料、同伴料、ドリンク、テーブルチャージ、サービス料等は基本的に10%課税。単に店舗側が「これは税を取りたくない」と設定して非課税にできるわけではない。消費税の非課税・不課税は取引の性質で決まる。（国税庁）「TAX込み調整」を非課税項目として伝票に入れる設計は原則避ける。課税売上の端数調整・値引きなら、元の課税売上に対応する値引きとして税額にも反映させる必要がある。（国税庁） | tax_category を料金項目単位で保持。ただし通常営業項目は初期値 taxable_10。非課税は自由入力ではなく限定的な選択肢にする。「TAX込み調整」は non_taxable ではなく discount / adjustment として処理。 |
| T5 内税/外税（C4） | 内税・外税の切替は可能。ただし「適用しない＝免税」は税計算方式ではなく、店舗自体が免税事業者かどうかの属性。課税事業者が任意に「今回は消費税適用なし」と選ぶものではない。適格請求書発行事業者は課税事業者に限られる。（国税庁）適格簡易請求書は、発行者名・登録番号、日付、取引内容、税率ごとの税込/税抜対価、適用税率または消費税額等が必要。飲食店なら相手方名称は不要。（国税庁）消費税の端数処理は商品ごとではなく、一伝票につき税率ごとに1回。切捨て・切上げ・四捨五入はいずれも可。（国税庁）値引きを税計算前に適用する設計でよい。むしろ通常はその方が自然。実際に受け取る対価が課税標準になるため。（国税庁） | price_mode = tax_included / tax_excluded と、別に business_tax_status = taxable / exempt を持つ。端数処理は 伝票 × 税率 ごとに1回。計算順は 料金→値引き→税率別集計→消費税算出→端数処理→請求額 が基本。 |
| T6 サービス料・カード手数料（C3/C4） | サービス料は通常10%課税。飲食店のサービス料・奉仕料・テーブルチャージ等は、料理代等とは別建てでもサービス提供の対価の一部とされる。（国税庁）一方、カード会社が加盟店から差し引く決済手数料は、典型的なクレジット債権譲渡型では消費税非課税。（国税庁）ただしここで重要なのは、店が客に「カード手数料5%」として別途請求するケースは別物ということ。カード会社から店に請求される加盟店手数料を、そのまま客への「非課税手数料」に変換できるわけではない。店舗自身が客から決済方法に応じて徴収する金額は、店舗の役務提供に関連して受け取る対価として、原則として本体売上と同様に課税処理するのが妥当。（国税庁） | service_charge は通常 taxable_10。カード会社へ支払う merchant_fee は売上伝票ではなく決済コスト／日報・会計側に持つ。客へ転嫁する場合は card_surcharge として別項目化し、原則 taxable_10。 |

## T4：「全項目課税」で固定するか

「全項目課税固定」より、税区分を項目ごとに持てるようにして、通常項目のデフォルトを10%課税にするのがいい。

夜職店舗で典型的に出てくる、セット料金・延長料金・指名料・場内指名・同伴料・ドリンク・ボトル・フード・テーブルチャージ・サービス料あたりは基本的に課税売上。なので UI 上で店側が何でも簡単に「非課税」にできる必要はない。むしろ「通常：課税10%／例外：非課税・不課税」という設計にした方が事故が少ない。

特に、今ある「TAX込み調整＝非課税」は変更した方がいい。

```
小計       18,000
サービス料  3,600
調整        -600
課税対象    21,000
消費税       2,100
合計        23,100
```

のように、課税対象売上に対する値引き・調整なら、その600円も課税売上側から減らすべき。「-600円だけ非課税取引が突然発生した」という処理にはしない。国税庁も、課税売上に対する値引きは「売上げに係る対価の返還等」として消費税額を調整する扱いにしている。

## T5：「内税・外税・適用しない」の3択は少し直したい

データ構造を分ける。

- 価格設定: tax_included（内税）/ tax_excluded（外税）
- 事業者区分: taxable（課税事業者）/ exempt（免税事業者）

は別概念。「内税 / 外税 / 適用しない」という同列3択にはしない。「免税事業者だから消費税を別計算しない」は店舗属性。

さらに invoice_registered = true/false・registration_number = Txxxxxxxxxxxxx も別途持たせる。これで:

- 課税事業者＋インボイス登録あり → 適格簡易請求書を発行可能
- 課税事業者＋登録なし → 通常レシートは発行できるが適格簡易請求書ではない
- 免税事業者 → 適格簡易請求書は発行不可

（適格請求書発行事業者として登録できるのは課税事業者だから。国税庁）

### 計算順

```
① 商品・料金を計算
② 値引き・割引
③ 税率別に集計
④ 消費税計算
⑤ 税率ごとに端数処理
⑥ 最終請求額
```

重要なのは「1商品ごとに消費税を切り捨てない」こと。A 1,111円・B 2,222円・C 3,333円について、A税・B税・C税をそれぞれ切捨てて合算する方式ではなく、「10%対象合計→税額算出→1回だけ端数処理」。適格請求書では一の請求書につき税率ごとに1回というルールがある。（国税庁）

## T6：「カード手数料」という名前を2種類に分ける

### A. 店 → カード会社（加盟店手数料）

客の会計 100,000円・カード会社から入金 96,500円・加盟店手数料 3,500円。これは客の伝票には載せない。NOX では gross_card_sales / merchant_fee / net_card_deposit のような決済集計側。典型的な信販会社によるクレジット債権譲渡型の加盟店手数料について、国税庁は非課税としている。

### B. 店 → 客（転嫁）

飲食代 100,000円＋カード利用料 5,000円として店が客から取る5,000円は全く別。「カード会社の非課税手数料を客に転嫁したから5,000円も非課税」とはならない。店舗が自分のサービス提供に関連して客から受け取る対価なので、通常は card_surcharge・tax_category = taxable_10 とするのが妥当。消費税の課税標準には、その役務提供について受け取る一切の対価が含まれる。（国税庁）

ただし、カード手数料を客に上乗せしてよいかどうかは消費税とは別問題。カードブランドや決済代行会社との加盟店契約で、カード利用客への手数料転嫁が禁止・制限されている場合がある。したがって NOX としては「カード手数料○%を設定できる＝どの店舗でも合法・契約上問題なく徴収できる」という仕様にはしない方が安全。

## C3/C4 の推奨構造

```
料金項目
 ├─ price
 ├─ tax_category
 │    ├─ taxable_10
 │    ├─ taxable_8
 │    ├─ exempt
 │    └─ out_of_scope
 └─ calculation_type
      ├─ normal
      ├─ percentage
      ├─ discount
      └─ adjustment

店舗設定
business_tax_status: taxable / exempt
price_display: tax_included / tax_excluded
invoice_status: registered / unregistered
tax_rounding: floor / round / ceil
```

- サービス料: service_charge・percentage=20%・taxable_10
- カード関係: merchant_fee → 決済集計側・客伝票には入れない／card_surcharge → 客への請求項目・原則 taxable_10

特に修正すべきは「TAX込み調整＝非課税」と「免税＝内外税と同じ選択肢」の2点。この2つを外せば C3/C4 の税設計は筋が通る。
