## 調査B: 課金単位（1名/1卓）の現行経路

### B1. units の決定点（全て `time_per='person' ? coalesce(people,1) : 1`・live 逐語）

| 箇所 | 逐語 |
|---|---|
| check_open | `v_units := case when v_tper = 'person' then coalesce(p_people, 1) else 1 end;`（開卓 set 行の qty） |
| check_time_charge_apply:43 | `v_units := case when v_chk.time_per = 'person' then coalesce(v_chk.people, 1) else 1 end;`（auto 店の set/ext ブロック再計算） |
| check_extension_add:37 | `v_units := case when v_chk.time_per = 'person' then coalesce(v_chk.people, 1) else 1 end;`（manual 店の延長行 qty）。★ext_shimei 行は v_units **非連動**（qty=1/cast・:63） |
| check_set_people:49-53 | `v_units := coalesce(p_people, 1)` → `update ... set qty = v_units ... where time_auto and fee_kind = 'set'`＝**set 行のみ追随** |
| **three-mirror** | check-calc.ts / receipt.ts に time_per リテラル**なし**（timeBlocksOf はブロック数のみ・units 非関与）。check_close は行の凍結 qty を按分するだけ（:78-81）＝**ミラーは units を再計算しない**（行凍結値を読む） |
| UI（表示のみ） | register-board:2591 `l.kind === "time" && check?.time_per === "person"` で「×N名」表示 |

★重要: **time_per の読み手はサーバ3 RPC＋表示1箇所に閉じている**。ミラー3面は qty 凍結値経由＝ルール単位化してもミラー改修は不要（行生成側だけが変わる）。

### B2. checks の snap 列（set/ext 系・live 全列）

`set_min, set_fee, ext_min, ext_fee, time_per, dohan_fee?, ext_menu_snap?, business_tax_status, price_display, tax_rounding, category_id?, category_name?, set_rule_id?, set_rule_name?`

ルール単位を snap する場合の追加列候補:
- `set_unit text`（'table'/'person'・set 解決ルールの単位凍結）
- `ext_menu_snap` の各要素へ `unit` キー追加（延長はメニュー単位＝ルールごとに単位が違い得るため列でなく snap 内・鏡像規律=教訓52 で core 側にも単位返却が要る）
- 現行 `time_per` は店既定＝フォールバック時の単位として残す

### B3. 延長行の qty/金額経路と「追加時点の人数で確定」

- 経路: 開栓時 `ext_menu_snap`（rule_id/duration_min/amount/label を凍結・mig0128 で区分フィルタ済み）→ `check_extension_add(p_check_id, p_rule_id?)` が snap から `v_emin/v_efee` を解決（:45）→ 行 insert `qty=v_units, line_total=v_efee*v_units`（:59-60）。
- **「延長は追加時点の人数で確定」の実装点＝check_set_people の where 句**（`fee_kind='set'` のみ qty 追随・extension は不触＝:52-53）。auto 店は mig0097 の2段 apply（①旧 units で経過ブロック凍結→②people 更新→以後の新ブロックのみ新 units）。

### B4. ルール単位 `pricing_rules.billing_unit`（仮）の論点整理（案出しのみ）

1. **優先関係**: ルール解決あり＝`billing_unit`（null＝店既定 time_per へフォールバック）／ルール0件（stores フォールバック）＝現行どおり time_per。→「null=店既定」の3値意味論（table/person/null）が既存の「null=全区分」「rank null=全ランク」と同型で一貫。
2. **snap 形**: set は `checks.set_unit`（1列）・extension は **ext_menu_snap 内 unit キー**（メニューごとに単位が違い得る）＋core の RETURNS へ unit 追加（→鏡像2点＝教訓52・resolve_core の RETURNS 変更は**呼び手全数走査＝教訓48**が要る）。
3. **check_set_people との整合**: set 行 qty 追随は「set_unit='person' のときのみ」へ条件変更（現行は time_per 参照）。凍結列を読むよう差し替え＝非遡及の一貫性が上がる。
4. **auto 店**: check_time_charge_apply は checks 凍結値（set_min/ext_min/ext_fee）ベース＝ext の複数メニュー・ルール単位とは元々未統合（延長メニューは manual 店の器）。auto 店のルール単位対応は**別論点**として切り出すのが安全（0124 判断E と同型の初版 manual 限定案）。
5. **dohan**: 現行 `dohanUnit × 人数`（UI プレビュー）・check_dohan_add 経路は cast 単位＝ルール単位の適用対象外とするのが自然（要裁定）。
