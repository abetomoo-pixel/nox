# DP-R 全画面再監査（構造照合・2026-08-21）

**教訓26**（本監査で新設）: **「要素の存在 ≠ 構造の一致」**。
モック反映の検収は要素チェックリストではなく **画面単位の構造照合** で行う＝
セクション構成・レイアウト・タブ構造・情報の置き場がモックと同形かを画面ごとに判定する。
**DP3-S の a 分類（要素が在る＝一致）はこの基準で無効**＝全画面を再監査する。

## 0. 監査の方法（自己申告ではない機械抽出）

| 面 | 抽出方法 |
|---|---|
| モック | `mock/pages-2026-08/*.html` を `HTMLParser` で **body の DOM 順に走査**し、`nav.tabs` のボタン列・`section.panel`・`div.card`・`cardhead>h2`・骨格クラス（`kpis`/`planbar`/`workflow`/`calendar`/`planner-grid`/`matrix`/`tablewrap` 等）を**出現順のアウトライン**として出力 |
| 実装 | 各ルートの `*.tsx` を正規表現で走査し、`<section>`・`<h1/h2/h3>` の実テキスト・`tab === "x"` の分岐・`nox-kpirow`/`nox-repsum`/`nox-calgrid`/`nox-seatgrid`/`nox-table` 等の骨格クラスを**ソース出現順**に出力 |
| 突合 | 両アウトラインを**上から順に並べ**、①タブ構造 ②セクションの個数と順序 ③レイアウト（1カラム/2カラム・カード同居/分離）④情報の置き場（どのタブ・どのカードに在るか）の4点で判定 |

★**モックのタブ実装は2枚だけ**（実測）: `nox-shift-management`（`nav.tabs` 5本）と
`nox-staff-system-settings`（`nav.tabs` 4本）。**他の12枚はタブを持たない縦スクロール**である。
うち `nox-pricing-settings` は `pagehead h1` を**3つ**持つ＝1ファイルに3画面を積んだ体裁、
`nox-analytics-dashboard` は `kpis` 帯を**4つ**、`nox-daily-report` は**2つ**持つ＝
1ファイルに複数ビューを積んだ体裁。**この「積み」を実装側のタブ/ビュー切替に写すのは構造一致とみなす**
（静的モックがビュー切替を表現できないことによる差＝意味の同形）。

判定語:
- **一致** = タブ構造・セクション構成・順序・レイアウト・置き場がすべて同形
- **部分一致** = 骨格は同形だが、欠落カード・順序違い・カード同居/分離の差がある
- **不一致** = タブ構成またはセクション構成が別物（モックの主要カードの過半が無い／置き場が違う）
