## 0. 裁定(Agoora 確定 2026-09-09)

| 裁定 | 内容 |
|---|---|
| C②-1 | 勤務パターン=店舗定義の名前付き枠(名前・開始・終了・effective_from)。シフト行は作成時に枠の時刻を行へ写し(凍結列)、例外は**その行の時刻を manager 以上が上書き**する。枠表に例外行は作らない |

## 8-実測(2026-09-09・CC)

live(nox-dev・proof=orgs 3)を直結 introspection で埋めた。読み取り専用・実装なし。

### 8-1 日跨ぎ時刻の既存表現
- cast の `shifts` / `shift_wishes` は **start_hm / end_hm とも text**(time 型ではない)。CHECK＝start `^([01][0-9]|2[0-3]):[0-5][0-9]$`(00:00〜23:59)・end `^([0-3][0-9]|4[0-7]):[0-5][0-9]$`(00:00〜47:59＝**30 時間制の 24h 超表記**で日跨ぎを表す。end < start ではない)。
- `stores.settings_json.biz_cutoff_hm` は文字列(実値: '07:00' 1 店・未設定 3 店＝code 既定 06:00)。営業日の判定は `bizDateOf(at, cutoff)`(lib/nox/biz-date.ts)。
- `store_business_hours.close_hm` も同流儀(30:00＝翌06:00・business-hours-panel で変換)。
- →§1.1 の「time not null・日跨ぎは end < start」は既存 3 表と**不一致**。揃えるなら text＋同 CHECK(24h 超表記)。

### 8-2 黒服の識別・自店判定ヘルパー
- `memberships`: id(pk)・user_id(fk users)・store_id(fk stores)・role(check: owner/manager/staff/cast)・is_active・can_register／can_crm／can_shift／can_view_backs(boolean not null)・unique(user_id, store_id)。**org_id 列なし**(org は stores.org_id 経由)。
- 黒服＝`role='staff'` の memberships 行。識別子は **memberships.id** か **users.id** のどちらか＝§1.2 staff_id の参照先を決める(既存の cast 系は casts.id・監査の actor は users.id)。
- ヘルパー(すべて SECURITY DEFINER・STABLE): `auth_org_id()` uuid／`auth_role()` text／`auth_store_id()` uuid／`auth_cast_id()` uuid／`auth_staff_can_shift()` boolean／`auth_staff_can_register()`／`auth_staff_can_crm()`／`auth_staff_can_view_backs()`／`auth_cast_can_register()`／`auth_org_billing_writable()`／kiosk 系 4 本。「本人」判定に使える staff 用の id ヘルパー(auth_membership_id 等)は**無い**＝黒服本人の RLS は `auth.uid()`→users.auth_user_id→memberships の結線を policy 内で書くか、ヘルパー新設。
- 標準店スコープの述語＝`org_id = auth_org_id() and (auth_role()='owner' or store_id = auth_store_id())`(CLAUDE.md・既存全表)。

### 8-3 audit_logs action の実名(shift／staff 系・live 件数)
shift_set 18／shift_wish_submit 7／shift_period_set 7／shift_propose 6／shift_bulk_set_daily 5／shift_bulk_set 4／shift_confirm_bulk 4／shift_wish_decide 4／shift_auto_apply 3／shift_remove 3／staffing_need_remove 3／shift_auto_clear 2／shift_period_remove 2／shift_rules_set 2／shift_cast_confirm 1／shift_wish_withdraw 1／staff_create 8／staff_deactivate 3／staff_reactivate 3／staff_change_role 2／staff_transfer_store 2／staff_update_profile 2。
- action は enum で縛られていない(0002: text・「RPC 名が入る」)＝再利用より **RPC 名をそのまま action にする現行流儀**。§2 の `staff_shift_override` はこの流儀に一致(新 action＝裁定不要・名簿更新のみ)。
- audit-board の「取消・巻き戻し」ビューは action の明示リスト(check_void…shift_wish_withdraw)＝黒服系を出すなら同リストへ追記。

### 8-4 cast shifts の status 語と shift_periods の粒度
- `shifts.status` check＝**planned / proposed / confirmed**(3 値・0101)。§1.3 の「proposed / confirmed」は planned を欠く(cast 側は「作成(planned)→確認依頼(proposed)→確定」の 3 段)。黒服は希望◯×→propose なので planned 段が要らないなら明示して 2 値でよい(語は同じ)。
- `shift_periods`: start_date／end_date／wish_deadline(**date**・時刻なし)／status check＝draft / open / closed / published。期間単位＝任意の日付範囲(月・半月は運用)。§1.4 の締切「N 日前・時刻」は cast 側の period.wish_deadline(date のみ)と型が違う＝黒服側だけ時刻付きになる点を v1 で明記。

### 8-5 /shift の現行タブ構成(H3 の差込位置)
- タブ＝**today(今日)／queue(承認待ち)／build(シフト作成)／calendar(仮シフト)／roster(確定シフト)**(shift-board.tsx `:197,715`・key "today" は裁定44 で据え置き)。
- 対象切替「キャスト／黒服・スタッフ」は現行なし。差込位置＝タブ帯の左(モック v4.1 73-79 行「確定シフト｜黒服・スタッフ」)＝flag off なら切替そのものを出さない(横断 §4)。B4(2026-09-09)で触った面＝today／queue／roster／DayAddPanel はすべて cast 前提で staff_shift に依存しない。

### 8-6 flag_enabled の signature と off 時の文言
- `flag_enabled(p_key text, p_store_id uuid default null) returns boolean`・STABLE・SECURITY DEFINER・search_path public。読取関数は **raise せず false**(fail-closed: key null→false・auth_org_id() null→false・他 org の store→false・店舗行→org 行→false)。
- `flag_set(p_key, p_store_id, p_enabled, p_reason) returns uuid`(裁定198)。raise 文言＝`'forbidden'`(null 引数・org null・owner 以外・他 org の store)／`'billing locked'`(課金ゲート)／`'unknown_key'`(4 key 以外)。
- C① で「off 時の書込 RPC の raise 文言」は**未定義**(C① は読取 RPC のみ)。本書 §2 の「off → raise」の文言は新規に決める＝候補 `'feature disabled'`(f0 の anon-guard／billing 段と同じ英字 1 語系)。
- `feature_flags` 列＝id／org_id／store_id(null＝org 既定)／key／enabled／updated_at／updated_by。
