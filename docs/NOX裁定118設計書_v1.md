## 0. 裁定(2026-09-03 確定・8件)

1. **方式B 表現先=(a) 新 fee_kind 'vip_charge'**(pricing_rules 行・resolve 解決・開栓時凍結)。
   products 案は手動=「席種で自動」未達で不採用。方式A は現行器(seat_kind='VIP' の
   set/extension ルール)で既に表現済み=追加実装なし
2. **課金単位=pricing_rules.billing_unit** text null・CHECK ('person','table')。
   **null=店既定(time_per)フォールバック**=「null=全区分」と同型の3値意味論。
   対象=set/extension/vip_charge。**dohan は対象外**
3. **#52 吸収**: 公開ラッパ pricing_resolve を 6引数化+whitelist を core と完全同期
   (ext_shimei/vip_charge 含む7種)。非対称解消
4. **vip_charge に区分を許可**: set_pricing_rule の区分 whitelist=set/extension/dohan/
   vip_charge の4種へ
5. **vip_charge の duration 不許可**(額のみ)。pricing_rules check2(duration は
   set/extension のみ)は現行のまま=無改修で fail-closed 成立
6. **category-map: vip_charge は既存 time 系(セット・延長と同区分)へ吸収**。新キー
   なし=日報 UI・写像 pin 23 の波及回避
7. **auto/manual 不問**: vip_charge 行は開栓時1回生成(set 行と同型)・
   check_time_charge_apply の upsert 対象にしない(fee_kind 不一致で自然に非対象=
   f0 で担保)
8. **person 単位 vip_charge は人数変更追随**: check_set_people の更新対象へ
   (凍結 unit='person' の行のみ)。「セット中の人数変更はセット料金に反映」の
   意味論と一致

## 1. 器(DB)

- pricing_rules:
  - fee_kind CHECK へ 'vip_charge' 追加(7種)
  - **billing_unit text null** 追加・CHECK (billing_unit in ('person','table'))。

  - rank check1(shimei 2種のみ)・duration check2(set/ext のみ)=無改修
    (vip_charge は rank 不可・duration 不可が自然成立)

  (kind CHECK 無改修)
- checks(snap 追加列・すべて nullable):
  - **set_unit text**: set の実効単位('person'/'table')を凍結。新規開栓は必ず値が入る・
    既存伝票=null(読み手は null→time_per フォールバック=後方互換)
  - **vip_charge_fee int / vip_charge_unit text**: dohan_fee 同型の nullable snap
    (ルール0件=null)
- ext_menu_snap: 各メニュー項目へ **"unit" キー**追加(実効単位)。旧 snap に unit なし
  =読み手は time_per フォールバック(後方互換)

## 6. f0 系統(118-1・新スイート verify-nox-vip-unit)

a) 互換: 既存ルール全 billing_unit null+vip_charge 0件=全経路現行同値(golden 6値不変)
b) vip_charge: VIP 席で行生成(額・qty=units)/非 VIP 席で非生成(seat_kind 条件)/
   区分付き vip_charge の一致・非一致/フォールバック=vip_charge_fee null・行なし
c) billing_unit: person×N名/table×N名/null=time_per 追随の3系統×set・ext・vip
d) 凍結: set_unit/vip_charge_unit/ext_menu unit キーの snap 実測+開栓後の
   ルール単位変更が非遡及
e) 人数変更: person 単位 vip_charge 行の qty 追随/table 単位は不変/extension 不触
f) 非干渉: check_time_charge_apply が vip_charge 行を upsert しない(auto 店実走)
g) ガード: 'bad unit kind'(dohan/shimei へ単位指定)・'bad fee kind' 旧経路・
   ラッパ 6引数化の互換(5引数相当呼び)
h) rate-back: vip_charge 行 back_snapshot=null=給与不干渉・rate-back golden 64 不変
逆試験=INVERT 全赤+破壊検出の両建て定型。
