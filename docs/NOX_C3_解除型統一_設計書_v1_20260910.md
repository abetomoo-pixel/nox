## 1. 表の変更(mig0138・alter のみ・新表なし)

### 1.1 memberships
| 列 | 型 | 備考 |
|---|---|---|
| can_close | boolean not null default false | 日報の締め・差異承認 |
| can_reopen | boolean not null default false | 日報/給与の解除 |
ヘルパー: `auth_staff_can_close()` / `auth_staff_can_reopen()`(auth_staff_can_shift と同型・authenticated 公開)。

### 1.2 daily_reports(8列)
| 列 | 型 | 備考 |
|---|---|---|
| reopened_at | timestamptz | null=未解除 |
| reopened_by | uuid fk memberships | |
| reopen_reason | text check(reopen_reason is null or length(trim(reopen_reason)) between 1 and 200) | |
| reclosed_at | timestamptz | 再締めで set・reopened_* は残す(履歴) |
| reclosed_by | uuid fk memberships | |
| diff_reason | text check(diff_reason is null or length(trim(diff_reason)) between 1 and 200) | 現金差異の説明 |
| diff_approved_by | uuid fk memberships | |
| diff_approved_at | timestamptz | |
制約: `check (reclosed_at is null or reopened_at is not null)`。解除→再締めを繰り返す場合は reopened_* を上書き(直近のみ・履歴は audit_logs)。reclosed_count は既存のまま +1。

### 1.3 checks
merged_into(休眠列)を実使用へ。status CHECK を open/closed/void → open/closed/void/**merged** へ張り替え(drop constraint → add)。merged 行は void と同じ述語で除外(C③-16・app 側 collect.ts 1 箇所)。stock 戻しトリガは void 限定のまま。

## 2. RPC

### 2.1 日報の解除・再締め・差異承認
| RPC | 権限 | 概要 |
|---|---|---|
| report_reopen(p_store_id, p_biz_date, p_reason) | owner/manager 自店・staff∧can_reopen | 締め済み行に reopened_* を set(解除中なら `already_reopened`)。audit `report_reopen` |
| daily_report_reclose(既存 7 引数+末尾 p_idem_key default null) | 同 daily_report_close | **解除中のみ**(`not_reopened`)。再集計→reclosed_at/by→reclosed_count+1。既存の「解除なし上書き」経路は廃止。client は idem_key を必ず渡す |
| cash_diff_approve(p_store_id, p_biz_date, p_reason) | owner/manager・staff∧can_close | 締め済み行に diff_* を set。差異式=`counted_cash − (cash_float + cash + ar_collected − expense − cash_payout)`(§8-8)。counted_cash null は `not_counted`(C③-18)・差異 0 は `no_diff`。audit `cash_diff_approve` |

### 2.2 締め済み日の関所(C③-2)
内部ヘルパー `assert_day_open(p_store_id, p_biz_date)`: flag_enabled('reopen_flow', p_store_id) が true かつ daily_reports に該当行があり解除中でなければ `raise 'day closed'`。flag off なら何もしない。課金ゲート内蔵の書込 RPC 16 本(§8-1 実名)の課金ゲート行直後(伝票行を select する RPC は select 後)に `perform` を 1 行。check_open は `biz_date_of(p_store_id, now())`(C③-15)。

### 2.3 check_merge(p_from_check_id, p_into_check_id, p_reason)
権限 owner/manager 自店。順に検証→raise: 同一伝票/別店舗 `forbidden`・双方 open でない `merge_conflict:status`・payments/receivables あり `merge_conflict:money`・重複 cast `merge_conflict:cast`・pay_group A 以外 `merge_conflict:pay_group`。
処理: check_lines/check_nominations/check_seats を into へ付け替え(seats は cascade 対象なので update)・from を `merged`+merged_into=into・`check_recalc(into)`(§8-3・トリガなし)。audit `check_merge`(target=into・before/after に両 id と line 数)。idem_key 必須(check_pay と同型)。

### 2.4 payroll_reopen(5 引数版新設・4 引数版 drop・C③-13)
service 経路は維持。route の authz は `decideReopenAccess(role, can_reopen)` 新設(C③-17・decideTaxReportAccess 不触)。本文冒頭で flag ゲート(reopen_flow off → raise)。p_reason は 1〜200 字判定。

### 2.5 set_staff_perms(7 引数=id+6 boolean)
既存 5 引数版を drop し 7 引数版(can_close/can_reopen 追加・boolean 明示)。呼出は staff-board 1 箇所を同時改修。audit 'set_staff_perms' 維持(C③-9)。

全 RPC: SECURITY DEFINER・null-guard→課金ゲート逐語行(段47-1 形 f)→flag ゲート→権限→入力検証。ACL は 0135/0136 形。
