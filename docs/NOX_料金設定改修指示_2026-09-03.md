# NOX 料金設定まわり 改修指示まとめ

(2026-09-03 Agoora 起草・要件正本。相談役突合済み:
 §1〜3/§7/§8=既裁定(115/116/117・設計ロック v1)と一致・現行レーンで消化。
 §4 プレビュー拡張=#52 待ちの独立レーン。§5 方式B+§6 課金単位=新規 money 設計レーン(裁定118 仮))

## 背景
現在の NOX「料金設定」は、
- 料金そのもの
- 料金の適用条件
- 会計・レジの計算ロジック

が混在しており、役割が不明瞭。

今後は下記3責務で整理する方針。

1. 料金マスタ = いくら請求するか
2. 料金適用ルール = いつ・誰に・何分・どの料金を適用するか
3. 会計設定 = レジでどう計算・確定するか

ただし、DB は分けない。
現行 `pricing_rules` を維持し、UI 上だけ責務別に見せ分ける。

---

# 1. 料金マスタ

## 役割
お客さまへの「請求額」の正本。

## 対象
- 本指名料
- 場内指名料
- 同伴料
- セット料金
- 延長料金
- 席種ごとの料金
- キャストランク別の指名料金

## 重要
「通常料金」「VIP基準料金」のような別マスタを新設しない。

現行 `pricing_rules.name` を表示名として利用し、
同じ `name` を持つルール群を UI 上でグルーピングして見せる。

つまり、

- UI上: 通常料金 / VIP料金 のように見える
- DB上: 現行 pricing_rules 行のまま

とする。

---

# 2. 料金適用ルール

## 役割
「いつ・誰に・何分・いくらを適用するか」の正本。

## 1ルール行が持つもの
現行器どおり、同一行に以下を持つ。

- 時間帯
- 曜日
- 席種
- 区分
- amount
- duration_min
- 延長金額
- 延長時間
- 優先順位
- 表示名(name)
- 有効/無効

## 重要
「入店時間ごとのセット時間」だけを独立ルールにしない。

DB上は、
`時間帯 + 金額 + セット時間`
を同じ pricing_rules 行として保持。

UI上だけ見やすく分離して見せるのは可。

例:
- 20:00〜21:00
  - セット ¥8,000
  - 60分
- 21:00〜23:00
  - セット ¥8,000
  - 50分

## 区分
裁定116に従い、条件列に「区分」を追加。

例:
- 通常
- 初来店
- 全区分

開栓時に区分を選択し、
その区分も pricing rule 解決条件に含める。

## 優先順位
裁定115②どおり。

- 上にあるルールほど優先
- 重複時は優先順位の高い行を採用
- 並び替え対応

---

# 3. 会計設定

## 役割
レジで「どう計算・確定するか」の正本。

## 対象
- 営業日切替時刻
- 自動延長
- サービス料
- カード手数料
- 内税 / 外税
- 課税 / 免税
- インボイス
- 税額丸め
- 最終金額丸め
- 会計確定前確認
- 締め後修正
- 監査ログ

## 時間課金の確定
選択式にしない。

現行 snap 体系に従い、

**伝票オープン時に固定**

とする。

UIでは選択肢ではなく固定表示。

区分も開栓時に凍結。

---

# 4. 料金プレビュー

現行「いま開卓したら」を再配置する。

入力:
- 入店日時
- 席種
- 人数
- 区分
- 同伴有無
- 支払方法

出力:
- 適用された pricing_rules 行
- セット料金
- セット時間
- セット終了時刻
- 延長料金
- 同伴料金

例:
20:30入店
→ 平日アーリー
→ ¥8,000 / 60分
→ 21:30セット終了

---

# 5. VIP対応

VIPは2方式に対応したい。

## 方式A
VIP専用セット料金

例:
- 通常席 60分 ¥8,000
- VIP 60分 ¥12,000
- VIP延長 30分 ¥7,000

## 方式B
通常料金 + VIPチャージ

例:
- 通常セット ¥8,000
- VIPチャージ +¥5,000

## VIP設定の置き場所
料金マスタ側に「VIP料金方式」を持たせる。

- VIP専用料金を使う
- 通常料金 + VIPチャージ

ただし DB 実装では、
VIPチャージを加算項目として現行器で表現できるか要確認。

---

# 6. 課金単位を追加

現状の料金設定には、
金額が「1名あたり」なのか「1卓あたり」なのかの区別がない。

これは追加必須。

## 追加する項目
課金単位:

- 1名あたり
- 1卓あたり

## 対象
少なくとも以下に対応する。

- セット料金
- 延長料金
- VIPチャージ

## 例

### 1名あたり
VIPセット
- ¥10,000
- 60分
- 1名あたり

2名入店なら ¥20,000

### 1卓あたり
VIPルーム
- ¥10,000
- 60分
- 1卓あたり

2名でも3名でも ¥10,000

### 組み合わせ例
- 通常セット ¥8,000 / 1名
- VIPチャージ ¥5,000 / 1卓

これも表現できるようにする。

---

# 7. UI原則

画面上は3タブ:

- 料金マスタ
- 料金適用ルール
- 会計設定

ただし DB は現行 pricing_rules を維持。

重要原則:

**UIは分ける、DBは分けない。**

---

# 8. 変更してはいけないもの

- pricing_rules を別マスタへ分割しない
- 「通常料金」「VIP基準料金」専用テーブルを新設しない
- セット時間だけのルール行を作らない
- 時間課金確定タイミングをユーザー選択式にしない
- snap / resolve / golden を壊す再設計はしない

---

# 9. 今回の目的

新しい大規模DB設計ではなく、
現行器を維持したまま、

- 金額
- 条件
- 会計ロジック

の責務を UI 上で明確に分け、
夜職店舗の実運用に耐える料金設定画面へ整理する。
