# E8 構成差マトリクス（13モック × 実画面・2026-08-18 起草／同日 裁定転記）

読み取り専用のプリフライト成果物 ＋ **裁定転記済み**（正本＝`docs/NOX_E8裁定_v1.md`）。

## 0. この文書の読み方

- **見ているのは情報構成の差だけ**（どの情報がどこにあるか）。色・角丸・余白・フォントの意匠差は
  デザインレーン E0〜E6 で解決済み＝本書の対象外。
- **モックの欠落は削除指示ではない**（機能の正本は repo・デザインの正本はモック＝ガイド §5 の原則）。
  「実装→モック欠落」行は「モック側に意匠を当てる先が無い」という意味であって、実装を削る話ではない。
- 分類 **[A]純レイアウト**＝データは既に画面に来ている（並べ替え・再掲で実現）／
  **[B]表示用データ不足**＝直 select か既存 RPC で取れる（取得元を根拠欄に）／
  **[C]新規機能**＝DB/RPC 新設が要る。
- 規模 **S**＝1カード程度／**M**＝複数区画の再配置／**L**＝画面全体の作り直し級。
- **裁定欄**の語彙: `採用（E8-n）`＝その段で実装／`現行維持`＝実装が正（モック欠落≠削除）／
  `後送り`＝post-launch 台帳へ（理由付き）／`ペンディング`＝再裁定待ち／`不採用`＝作らない確定／
  `裁定0型`＝差ではなく裁定済みの非追随として台帳固定／`要確認`＝裁定書に判断が無い残点。
- 採取方法: モック HTML のクラス/見出しの機械抽出＋実装 tsx の見出し・タブ・表の突合（並列5系統）。
  **行番号は 2026-08-18 時点**。分類は CC の一次判定＝裁定で覆して構わない。
