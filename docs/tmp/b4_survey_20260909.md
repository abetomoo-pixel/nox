## 裁定要点（B4 着手前・10 点）

1. **H18 定義**: 希望どおり＝shift.wish_id の wish と start/end が一致・要調整＝不一致（両方あり）・未処理＝pending wishes 件数・申請者＝その distinct cast。
2. **H20 既定**: 「日付順／人ごと」の切替を置き、既定は人ごと（モック）か日付順（現行）か。推奨＝切替を置き既定は現行の日付順（見え方を変えない）。
3. **H31 置換か追加か**: 現行 4 枚（出勤予定／確定／未承認／不足）＋予想人件費を残し、モック 4 枚（出勤予定／出勤済み／遅刻・未着／欠勤）は**本日の勤務表の上に小さな 4 カウンタ**として追加（既存 KPI は不触）を推奨。
4. **H31「未着」の定義**: attendance 未記録 かつ 開始時刻を経過 かつ 打刻 'in' なし（打刻ありは「出勤済み」扱いに寄せる）。
5. **H32 表示**: 当日 punches の最終 'in' を「HH:MM打刻」として出勤記録セルの補助表示（book は attendance・書込なし）。cast 自身の打刻は /mine（punch_self）のまま。
6. **H37**: 「印刷」ボタン＝window.print＋`.nox-printpage` 隔離で確定一覧のみ印刷（PDF はブラウザ印刷）。CSV は残す。
7. **H39**: owner のみ「確定後の変更履歴」（表示月・シフト系 action・target の shifts:id を名前へ解決）・manager 非表示・「管理者変更を追加」は出さない（裁定190 同型）。
8. **H41**: DayAddPanel に名前部分一致の検索 input のみ（勤務条件表示は H15 後）。
9. **H27 部分**: 「確認済み／未確認」の人別リストを確定シフトタブへ（proposed／confirmed の再形・変更希望／辞退希望／催促は出さない）か、据え置きか。推奨＝出す（2 値だけ・件数 KPI 2 枚）。
10. **H4**: 据え置き推奨（「半月単位で作成」は shift_periods の粒度運用と同時・表示だけの前半／後半絞込は混乱要因）。

## C層②（黒服シフト・feature_flags staff_shift）との境界

- code 側で `flag_enabled`／`staff_shift` を読む箇所は **feature-flags-panel（表示・切替 UI）と verify のみ＝0 面**（app 内 grep 0）。dev の feature_flags は 0 行＝全 key false（fail-closed）。
