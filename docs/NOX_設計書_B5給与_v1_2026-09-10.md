## 3. 画面

### 3.1 月次一覧（新設・page.tsx 起点）
- 到達: owner / manager のみ。他ロールは現行通り /register へ redirect（cast は /mine）
- スコープ: owner=全店・manager=自店（auth_store_id）。RLS（payroll_runs select policy）越しの select のみ・route 不要
- 切替: nox-seg「店舗別 / 月別」（B4 H20 写し）
  - 店舗別: 選択店の期間降順
  - 月別: 選択期間の店舗一覧
- 行: 店舗 / 期間 / status バッジ（draft / finalized / paid＝既存 418〜427 再利用）/ 対象者数 / 総支給 / 差引支給 / 支払状況（payment_records 件数・合計）/ 更新日時 / 操作
- KPI 4枚（B4 H18 写し・選択スコープの合計）: 対象者 / 総支給 / 差引 / 支払済み件数
- 操作列: 「明細へ」（既存 board へ storeId＋period で遷移）/ CSV（status ∈ {finalized, paid} で活性）/ 支払済みにする（owner・finalized のみ）
- 変更履歴列（owner 限定・B4 H39 写し）: 直近 action と reason・折りたたみ
- 印刷: nox-printpage 隔離（B4 H37 写し）・一覧のみ

### 3.2 既存 payroll-board
- 変更なし（確定/解除/CSV は現行のまま）。一覧からの遷移で store×period を初期選択に受ける（query or props）
- 節「確定を解除」の理由 input・payCount ガードは現行維持

### 3.3 支払済み化（新設・B5-6）
- 一覧の操作列ボタン → 確認ダイアログ（店舗・期間・差引合計を表示）→ POST /api/payroll/mark-paid
- 活性: owner ∧ status='finalized'。RPC の既存判定（payment_records 有無等）に反する場合は RPC の返却文言をそのまま表示
- 成功後 status='paid' に再描画（楽観更新しない・再 select）
