## 2. RPC

### 2.1 日報の解除・再締め・差異承認
| RPC | 権限 | 概要 |
|---|---|---|
| report_reopen(p_store_id, p_biz_date, p_reason) | owner/manager 自店・staff∧can_reopen | 締め済み行に reopened_* を set(解除中なら `already_reopened`)。audit `report_reopen` |
| daily_report_reclose(既存 signature+p_idem_key) | 同 daily_report_close | **解除中のみ**(`not_reopened`)。再集計→reclosed_at/by→reclosed_count+1。既存の「解除なし上書き」経路は廃止 |
| cash_diff_approve(p_store_id, p_biz_date, p_reason) | owner/manager・staff∧can_close | 差異ありの締め済み行に diff_* を set。差異 0 は `no_diff`。audit `cash_diff_approve` |

### 2.2 締め済み日の関所(C③-2)
内部ヘルパー `assert_day_open(p_store_id, p_biz_date)`: flag_enabled('reopen_flow', p_store_id) が true かつ daily_reports に該当行があり解除中でなければ `raise 'day closed'`。flag off なら何もしない。check_* 5本(§8-1 の実名)の null-guard 直後・課金ゲート後に `perform` を1行挿入。

### 2.3 check_merge(p_from_check_id, p_into_check_id, p_reason)
権限 owner/manager 自店。順に検証→raise: 同一伝票/別店舗 `forbidden`・双方 open でない `merge_conflict:status`・payments/receivables あり `merge_conflict:money`・重複 cast `merge_conflict:cast`・pay_group A 以外 `merge_conflict:pay_group`。
処理: check_lines/check_nominations/check_seats を into へ付け替え(seats は cascade 対象なので update)・from を `merged`+merged_into=into・into の合計は既存の再計算経路を呼ぶ(§8-3)。audit `check_merge`(target=into・before/after に両 id と line 数)。idem_key 必須(check_pay と同型)。

### 2.4 payroll_reopen(既存 8 引数版・p_reason 追加)
service 経路は維持。route(/api)側の authz を owner 固定→ owner/manager/staff∧can_reopen へ。本文冒頭で flag ゲート(reopen_flow off → raise)。p_reason null は `forbidden`。

### 2.5 set_staff_perms(6 引数)
既存 5 引数版を drop し 6 引数版(can_close/can_reopen 追加)。audit 'set_staff_perms' 維持(C③-9)。

全 RPC: SECURITY DEFINER・null-guard→課金ゲート逐語行(段47-1 形 f)→flag ゲート→権限→入力検証。ACL は 0135/0136 形。

### 8-1 関所を入れる check_* の実名と挿入位置
- 課金ゲート内蔵の check_* 書込 RPC は **16 本**: check_add_line／check_add_seat／check_close／check_dohan_add／check_extension_add／check_line_set_group／check_move_seat／check_open／check_pay／check_remove_line／check_remove_seat／check_set_nominations／check_set_people／check_shimei_add／check_time_charge_apply／check_void。
- 各本文のゲート行は逐語 `if not public.billing_writable_of(v_org) then raise exception 'billing locked'; end if;`(check_void のみ `public.auth_org_id()` 版)。「null-guard 直後・課金ゲート後」＝この行の**直後**に `perform public.assert_day_open(v_store, v_biz_date)` を差す(v_chk を select する前の本文では店・営業日が未確定＝check_close／extension_add／remove_line／time_charge_apply／void は `select * into v_chk` の**後**に置く。open 系は p_seat_id→seats.store_id と now() の営業日で判定)。
- **5 本に絞る場合の候補**(締め済み日の金銭記録を動かす順): check_pay／check_close／check_void／check_add_line／check_remove_line。§0 C③-2 の「5 本」はこの 5 本を想定＝残り 11 本(席・人数・指名・延長・時間料金・グループ)も金額を動かす(extension_add／time_charge_apply／shimei_add／dohan_add／set_people／line_set_group)＝**関所の射程を 5 本にするか 16 本にするかは v1 で明記**。

### 8-2 checks.status の CHECK と void 除外述語
- CHECK 逐語: `CHECK ((status = ANY (ARRAY['open'::text, 'closed'::text, 'void'::text])))`＝`merged` を足すには CHECK の張り替え(drop→add・既存行は影響なし)。
- DB 側で 'void' を述語に持つ関数＝4(check_void／drink_claim_decide／drink_claim_void／drink_claims_on_line_delete)。トリガ `checks_stock_void`(AFTER UPDATE・old.status<>'void' and new.status='void' → stock_on_check)＝**merged では在庫戻しが走らない**(merge は行を移すだけなので正しい)。
- app 側の void 除外＝`lib/nox/payroll/collect.ts:278 .neq("checks.status","void")` の 1 箇所(日報 aggregate は `status='closed'` で絞るため merged は自動除外)。register のフロア／一覧は `status='open'` 取得＝merged は自動的に消える。**→ `merged` 追加で直す述語は collect.ts の 1 箇所(`.not.in` へ)**。

### 8-3 伝票合計の再計算経路
