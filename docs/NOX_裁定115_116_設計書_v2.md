## 2. 裁定① snap 収載範囲(115)【確定: A=現行踏襲】

snap は「開栓時点で適用可能な全件」のまま。窓外ルールの手動選択(裁量適用)は導入しない。
理由: 開栓時凍結の原則維持・価格正統性の snap 検証可能性・裁量減免は approval 経路が正道・複数尺要件は A のまま充足(実測済み)。

## 3. 裁定② 既定の明示制御(115)【確定: A=器無改変】

既定=priority 最小を明文化。UI(帯編集)で帯内並び替え(priority 付け替え)を可能にし「一番上が既定として自動適用」を表示。is_default 列は新設しない。resolve 系無改変=golden 安全。

## 4. 裁定③ 区分軸の器(116)【確定: B=区分テーブル+null 許容 FK】

### 器

```
pricing_categories(
  id uuid pk default gen_random_uuid(),
  org_id uuid not null, store_id uuid not null,
  name text not null,            -- 「通常」「初来店」等
  sort int not null default 100,
  active boolean not null default true,
  created_at timestamptz not null default now()
)
-- RLS: 他マスタ同型(org/store スコープ)。unique(store_id, name) where active
alter table pricing_rules add column category_id uuid null
  references pricing_categories(id);  -- null=全区分
```

既存行は全て category_id=null=全区分 → **既存挙動・golden 完全無改変**。

### 解決規則

resolve の where に `(category_id is null or category_id = p_category_id)` を追加。
順序: **priority 第一鍵は維持**。同 priority 内でのみ区分一致 > null(全区分)。既存データ全 null につき順序不変。
**鏡像規律(実測で確定)**: 区分条件は pricing_resolve_core 側と check_open 内 ext_menu_snap の where **両方へ同時挿入**。片方だけは snap と請求の乖離を生む(→§8 教訓候補)。

### check_open 6引数化

`+ p_category_id uuid default null`(末尾追加)。
- kiosk はキー無送信=現行同値で互換(0125 kiosk 方針と同型・実測確認済み)
- 旧5引数は**明示 DROP**(恒久注意#3・0125 shift_set の型)+新へ revoke public/anon+grant authenticated
- named-args UI は後方互換
- snap に category_id/category_name を凍結記録(snapshot 強化)

### 開栓モーダル

店の active 区分 0件 → セレクタ非表示・null 送信=現行完全同一。1件以上 → セレクタ表示・既定=sort 最小。

### 初来店の移行と approval 用途分離(⑤実測で裏付け)

- approval 権限(live 実測): **申請**=owner/manager(自店)/staff(自店∧can_register)/cast(自店∧can_register)——「会計書込ゲート=check_add_line と同一」と本文コメント明記。**承認**=owner/manager(自店)のみ。approval_direct も owner/manager のみ。grants: 3本とも anon=false/authenticated=true
- 現行の「初来店つなぎ運用」(approval reason 固定文言)は 116 実装後に区分「初来店」へ移行
- approval 経路は裁量減免用として存続。権限面の矛盾なし(申請広め・承認は管理者固定のまま)

## 5. 裁定④ 重複警告の区分対応(116)【確定】

帯重複警告の判定単位: (fee_kind, 窓) → **(fee_kind, 窓, 区分)**。
- 同一区分同士の窓重複 → 警告
- null(全区分) vs 任意区分の窓重複 → 警告(null は全区分に効くため実質重複)
- 異なる区分同士 → 警告しない(並存が正常)
