## 1. 適用期間(effective_from 型)

**型**: 期間を持つ設定は `effective_from date not null` のみ持つ。終了日は持たない。
同一キー(店舗×対象)内で次の行の `effective_from` が前の行の終了となる。

| 規則 | 内容 |
|---|---|
| 重なり禁止 | 同一キーで同じ `effective_from` は unique 違反 |
| 過去日禁止 | 新規行の `effective_from` ≥ 営業日(当日)。既存行の日付変更は不可(削除→再作成) |
| 遡及なし | 伝票は開栓時・給与は締め時に凍結済み(freeze-at-open / close 凍結)。設定変更は凍結済み値に影響しない |
| 解決 | 「営業日 D に有効な行」= `effective_from ≤ D` の最大行。無ければ既定(店舗基本) |
| 削除 | 未来行のみ削除可。当日以前の行は削除不可(履歴) |
| UI | 「◯日から」1入力。一覧は現在有効行+予約行を表示。過去行は折りたたみ |

**適用対象(ローンチ範囲)**: C層② 勤務パターン・希望方式/確定単位/締切。
**適用対象(第2期)**: 入店時給保証・4段時給・在籍状態(履歴側で同型)。
**非対象**: pricing_rules(既存の dow/time_from/to 型を維持・本型へ移さない)。

## 2. 権限4層(役職既定+個別付与)

**型**: 役職で既定を決め、黒服のみ人ごとの付与で拡張。既存の黒服4権限(会計/顧客/シフト/バック=boolean・`set_staff_perms`)と同じ方式で **2列追加**。

| 操作 | owner | manager | 黒服 既定 | 黒服 付与 | キャスト |
|---|---|---|---|---|---|
| 見る(各面) | ○ | ○ | 既存4権限 | 既存4権限 | 自分のみ |
| 書く(通常操作) | ○ | ○ | 既存4権限 | 既存4権限 | 自分の申請 |
| **締め**(日報締め・現金実査) | ○ | ○ | × | `can_close` | × |
| **解除・承認**(締め解除/給与確定解除/現金差異承認/伝票統合) | ○ | ○ | × | `can_reopen` | × |
| 権限変更・フラグ切替 | ○ | manager 以下のみ | × | × | × |

| 規則 | 内容 |
|---|---|
| 付与できる人 | owner / manager(黒服が黒服に付与不可) |
| 既定 | 新規黒服は `can_close=false, can_reopen=false` |
| RPC 側 | 解除型 RPC は `auth_role() in ('owner','manager') or (auth_role()='staff' and perm)` を null-guard の直後で判定。fail-closed |
| 監査 | 付与・剥奪は監査10種「権限変更」に記録 |
| 保持単位 | **memberships**(store 単位)。既存 can_register/can_crm/can_shift/can_view_backs と同居。set_staff_perms は6引数化(C層③ mig に同梱・A6 名簿更新) |
| 既存との関係 | `request_accept/reject` の店長代理承認(guard なし)は現状維持。本表はそれを狭めない |

**C層②③の依存**: ③解除型は `can_reopen`、締め系は `can_close`。②黒服シフトの承認は manager 以上(黒服の自分シフトは申請のみ)。

## 3. 監査10種(共通1表)

**型**: 既存 `audit_logs` に統一。新表は作らない。取り消し困難な操作は **必ず** 以下を書く。

| 列(設計名) | 必須 | 内容 |
|---|---|---|
| action | ○ | 下表10種の固定値(自由文字列を新規に増やさない) |
| target | ○ | 対象 id(伝票/日報/給与期間/スタッフ/フラグ key) |
| before_json | ○ | 変更前の要点(金額・状態・権限値) |
| after_json | ○ | 変更後 |
| reason | 解除系のみ○ | 自由記述(1文字以上)。UI で必須入力。**現行列なし → C層① mig で `reason text` 追加・`audit_log_write` に `p_reason` を末尾追加(既定 null・既存呼出不変)** |
| actor | ○ | 既存 `actor_user_id` |

| # | action | 発生元 | reason |
|---|---|---|---|
| 1 | report_reopen | 締め解除 | 必須 |
| 2 | report_reclose | 再締め | 任意 |
| 3 | payroll_reopen | 給与確定解除(D-1) | 必須 |
| 4 | cash_diff_approve | 現金差異承認 | 必須 |
| 5 | check_merge | 伝票統合 | 任意 |
| 6 | check_void | 伝票 void | 必須 |
| 7 | price_snap_fix | 料金凍結値訂正(#61 型) | 必須 |
| 8 | perm_change | 権限変更(4+2 権限・役職) | 任意 |
| 9 | flag_toggle | フラグ切替 | 任意 |
| 10 | staff_deactivate | 在籍解除(スタッフ/キャスト) | 任意 |

| 規則 | 内容 |
|---|---|
| 書込主体 | RPC 内(SECURITY DEFINER)で `audit_log_write`(原則6)。クライアントから直接書かない |
| 検証 | 各解除型 RPC の f0 に「audit 行が1本増える・before/after が非 null・reason 必須なら空で raise」を含める |
| 閲覧 | 監査画面(既存)で action 10種をフィルタ可。owner/manager のみ |
| retention | ローンチ後必須(#58 付記)。本書では決めない |
| 既存 action | 既存の自由文字列 action は維持。10種はそれに追加 |

## 4. feature flag(二層)

**型**: `feature_flags` **新表**。org 行が既定、店舗行があれば優先。stores.settings_json(既存3キー: biz_cutoff_hm/cast_register_enabled/okuri_mode)には置かない(設定と機能公開を混ぜない)。

| 列(設計名) | 内容 |
|---|---|
| org_id | 必須 |
| store_id | null=org 既定 / 値=店舗上書き |
| key | 文字列(下表・code 側の定数と一致) |
| enabled | boolean |
| unique | (org_id, store_id, key)(store_id null は org に1行) |

| key | 対象 | ローンチ時既定 |
|---|---|---|
| staff_shift | C層② 黒服シフト+勤務パターン | off |
| reopen_flow | C層③ 解除型統一+check_merge | off |
| qr_order | QR 注文(ポストローンチ) | off |
| notify | 通知基盤(T3 ゲート後) | off |

| 規則 | 内容 |
|---|---|
| 解決 | `flag_enabled(key)`: 店舗行 → org 行 → false(fail-closed)。SECURITY DEFINER・null-guard |
| 切替できる人 | owner のみ。店舗設定に owner だけ表示 |
| 監査 | 切替は「flag_toggle」 |
| UI 出し分け | flag off = 導線・画面を出さない(disabled 表示にしない)。RPC 側も off なら raise(UI だけで隠さない) |
| ACL | 表は authenticated から select のみ・書込は RPC(revoke all from public, anon, authenticated → grant select) |
| key の追加 | 本書の表に追記=裁定。code 側定数と f0 の名簿を同時更新 |
