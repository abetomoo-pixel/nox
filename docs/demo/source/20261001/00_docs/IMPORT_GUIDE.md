# 開発用の読み込み手順

## 1. このパッケージの位置づけ

JSON/CSVのフィールド名は本パッケージ独自の中間形式です。
画面項目に寄せていますが、NOXの実DBのテーブル名・列名を確認したものではありません。
既存の認証・店舗権限・監査ログ・料金計算を迂回して本番に流し込まないでください。

`nox_demo_all.json` は `meta` と `datasets` を持ちます。
各datasetは `section` と `records` からなります。
種類別JSONも同じrecordsを格納し、CSVは同内容の確認・変換用です。
文字列中の配列はCSVではJSON文字列、真偽値はtrue/false、nullは空欄です。
空欄と0は区別してください。unknownの人数・時刻・明細を0とみなさないでください。

## 2. 設定の読み込み順

1. stores → categories → products → tables
2. pricing_rules → nomination_ranks → compensation_plans
3. people → person_plan_assignments
4. customers
5. 検証用データを選択（下記のAまたはB）

率はbpsです。DBが0.20を受け取るのか20を受け取るのかを確認し、変換してください。
商品マスターの会計区分はドリンク／シャンパン／ボトル／フードのUI区分に対応します。
表示カテゴリは別IDです。商品名だけで結合せず、store_idと固定IDを使います。

## 3. デモ用途を分ける

### A. 計算・回帰テスト

`03_reference_receipts` の6伝票を、隔離されたテスト店舗へ変換して登録します。
商品・料金・指名・会計・報酬が一致するか、添付のexpected_resultsと比較してください。
このパッケージのPython検証に加えて、NOX本体側での試験が必要です。
単独スライドテストは計算関数に与える入力例で、実日次売上レコードではありません。

### B. 画面用の仮データ

`02_september_targets` と `05_live_targets` は集計・UIフィクスチャ用です。
実績イベントとして計上するのではなく、独立したデモ表示層で使ってください。
未実装機能を有効化する目的でフラグだけ立てることは避けます。
売掛・在庫は開始スナップショット方式とイベント方式のどちらかに統一します。

## 4. 保留するデータ

多段ボーナス、指名ボーナス、ポイント自動付与、新人保証自動終了、スタッフへの商品バック、
ACEのVIP延長課金、時給スライド適用日は、本体仕様が確認できるまで保留してください。
表に存在することと、現行NOXでそのまま処理できることは別です。

9月勤務・売上のこころ分は入店前なので除外対象です。
報酬の参考計算を給与確定テーブルへ書き込まないでください。

## 5. リセットと二重計上防止

本パッケージのIDを、テナント内で安全なUUIDなどへ一括対応づけしてください。
ID対応表は保持し、同じ処理で別IDを無限作成しないようにします。
イベントの二重再生、売掛開始残高＋売掛起票の二重計上に注意してください。
リセット対象はこのデモ専用の店舗・レコードだけに限定します。
このパッケージには削除SQLや本番更新スクリプトを含めていません。

## 6. 検証

```bash
python 06_validation/validate.py
```

実行結果は `06_validation/validation_report.json` に保存されます。
PASSは参照モデルの計算検証を意味し、本体の統合試験ではありません。
