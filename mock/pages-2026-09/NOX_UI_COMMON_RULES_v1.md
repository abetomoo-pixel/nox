# NOX 管理画面 共通UIルール v1

報酬プラン管理で確定したルールを、他のNOX管理画面にも横展開するための共通基準。

## 1. 色の意味を固定する
- **Gold / Brand**: NOXブランド、重要見出し。通常操作には使わない。
- **Blue / Primary**: 操作・選択。追加、保存、編集、選択中タブ、フォーカス。
- **Green / Success**: 保存済み、完了、有効など正常完了状態。
- **Yellow / Warning**: 事前に知る必要がある注意。現在エラーではない。
- **Red / Danger**: 未保存、エラー、無効な入力、現状のままだと問題になる状態、ユーザーの対処が必要な状態。
- **Gray / Neutral**: 説明、補足、仕様注記。

### アラート判定例
- 「指名実績バックと商品販売バックは別系統で両方加算」→ **Neutral**
- 「保存操作が必要」だが変更前 → **Warning**
- 実際に変更済みで未保存 → **Danger**
- 「画面に見える設定が現行計算には反映されない」→ **Danger**

## 2. ボタンを同一コンポーネント化する
### Primary Action（青）
同一の高さ・角丸・文字サイズ・余白を使う。
- `＋ 報酬プランを追加`
- `歩合・バックを保存`
- `編集`
- `＋ カスタムバックを追加`

### Secondary（中立）
- 複製
- キャンセル
- 戻る
- 閉じる

### Danger（赤）
- 削除
- 無効化
- 取消など不可逆・危険操作

「追加」「保存」「編集」ごとに別デザインを作らない。

## 3. 入力欄の単位を常時表示する
ラベルだけに単位を置かない。入力中も単位を見失わないよう、入力欄の prefix / suffix として表示する。

### 入力例
- 金額: `¥ 5,000`
- 割合: `20 %`
- 1件固定: `¥ 4,000 円/本`
- ポイント: `500 pt`
- 時間: `6.0 h`
- 日数: `20 日`

金額・割合・本数・pt・時間が同一画面に混在することを前提にする。

## 4. 計算方式切替時は単位UIも同時に切り替える
例: 本指名バック
- 固定額選択 → `¥ 4,000 円/本`
- 割合選択 → `20 %`

固定額なのに `%` の入力欄が残る、割合なのに `円/本` が残る状態を作らない。

## 5. 一覧と入力で表記を使い分ける
### 入力フォーム
記号ベースで素早く認識できる表記。
- `¥ 5,000`
- `20 %`

### 一覧・サマリー
自然言語で意味が読める表記。
- `5,000円`
- `4,000円/本`
- `20%`
- `150,000円以上`

## 6. 段階設定は固定列にする
スライド等の `1段 / 2段 / 3段` は独立した固定幅列に置く。
各行で判定基準・結果の入力開始位置を揃える。

## 7. テーブル・一覧の罫線
- ヘッダ下線を必須。
- 各行に薄い下線。
- 列が判別しづらい一覧では薄い縦罫線も使う。
- 罫線は情報階層を補助するために使い、強すぎない。

## 8. タブ
- 選択中: 青背景（soft）＋青の下線。
- 2段以上に折り返す場合、上下のタブ行の間に必ず罫線を出す。
- 折返しによって「上段3つと下段3つの所属」が曖昧にならないこと。

## 9. 文字サイズ
- ページタイトル: 24–28px
- 大セクション見出し: 16–18px
- 小セクション見出し: 14px
- 本文・入力値: 13–15px
- ラベル: 12px
- 補足・注記: 10–11px
- 10px未満は原則使用しない（ブランド補助等を除く）。

## 10. 余白
- カード内: 16–20px
- 大セクション間: 18–24px
- フィールド間: 10–12px
- ラベル→入力: 6px前後
- テーブル行高: 44–48px

## 11. 保存状態
- セクション単位で保存する。
- 保存済み: Green
- 編集中・未保存: Red
- 保存対象外: Neutral
- 未保存時だけ、タブにも小さな状態ドットを表示してよい。
- 自動保存しない画面では、通常時の説明はWarning、実際に未保存変更が発生したらDangerへ変える。

## 12. レスポンシブ
- 幅が狭くなっても文字を極端に縮小しない。
- 入力カードは必要に応じて3列→2列→1列に落とす。
- `固定額（円/本）` 等の長い選択肢は重ねない。必要なら2行表示する。
- タブの折返し境界には罫線を入れる。

## 13. 基本原則
**色・文字・余白・罫線・ボタンはページごとに再設計しない。共通トークンと共通コンポーネントを使う。**

個別ページでは「情報構造」だけを設計し、見た目の基本ルールはこの共通基準を継承する。
